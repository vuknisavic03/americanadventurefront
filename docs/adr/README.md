# Architecture Decision Records

Architecture Decision Records capture material technical decisions that affect maintainability, security, portability, data ownership, integrations, deployment, or future commercialization.

## Naming

Use sequential names such as `0001-record-architecture-decisions.md` and `0002-target-application-architecture.md`.

## Lifecycle

Allowed statuses are `Proposed`, `Accepted`, `Superseded`, and `Rejected`. Do not edit the rationale of an accepted ADR to make history look different. Add a superseding ADR instead.

## Required sections

- Status
- Date
- Context
- Decision
- Consequences
- Alternatives considered
